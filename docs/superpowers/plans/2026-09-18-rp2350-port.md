# RP2350 port (Waveshare RP2350-PiZero)

## Target

Waveshare RP2350-PiZero: RP2350B (48 GPIO), 2x Cortex-M33 @ 150 MHz
(overclockable), 520 KB SRAM, 16 MB QSPI flash, optional QSPI PSRAM on
QMI CS1 (GPIO47, pad unpopulated from the factory), mini-HDMI wired to
GPIO32-39 (PIO only -- HSTX is hard-wired to GPIO12-19), microSD on SPI1,
native USB on USB-C #1, PIO-USB host on USB-C #2 (GPIO28/29).

Pin assignments (from the XRoar RP2350-PiZero port, which states they were
checked against the Waveshare schematic):

| Function          | GPIO                                    |
|-------------------|-----------------------------------------|
| UART0 TX / RX     | 0 / 1                                   |
| microSD           | SCK 30, MOSI 31, MISO 40, CS 43, CD 22  |
| HDMI TMDS D2/D1/D0/CLK | 32-33 / 34-35 / 36-37 / 38-39      |
| PIO-USB D+ / D-   | 28 / 29                                 |
| PSRAM CS          | 47 (QMI CS1)                            |

### SPI display with touch (TJCTM24028-SPI)

2.8", 320x240, ILI9341 display controller, XPT2046 resistive touch
controller.  The display is driven by a PIO state machine (which expands
the 1 bpp framebuffer to RGB565 without the CPU), the touch controller by
SPI0.

| Display pin | RP2350 | Header pin | Notes                                  |
|-------------|--------|-----------:|----------------------------------------|

| GND         | GND    |          6 |                                        |
| CS          | GP24   |         18 | display chip select                    |
| RESET       | GP23   |         16 |                                        |
| DC          | GP25   |         22 | data / command                         |
| SDI (MOSI)  | GP11   |         19 | PIO                                    |
| SCK         | GP10   |         23 | PIO                                    |
| LED         | GP21   |         40 | backlight; or straight to 3V3          |
| SDO (MISO)  | --     |         -- | not connected                          |
| T_CLK       | GP6    |         31 | SPI0 SCK                               |
| T_CS        | GP8    |         24 | touch chip select (software)           |
| T_DIN       | GP7    |         26 | SPI0 TX                                |
| T_DO        | GP20   |         38 | SPI0 RX                                |
| T_IRQ       | GP9    |         32 | low while the panel is touched         |

Many of these modules have a 3.3 V regulator and a solder jumper J1 that
must be closed when the module is powered from 3.3 V (bypassing the
regulator).  Powered from 5V instead, J1 stays open.  Signal levels are
3.3 V either way.  The SD slot on the back of the module is not used.

## Constraints

* Video must not occupy a whole core.  pTOS and its display output share
  core 0; core 1 is left for applications.  Preferred path: HSTX driving an
  external DVI connector on GPIO12-19 (hardware TMDS encoder, DMA straight
  from the framebuffer).  Fallback: PIO on the onboard HDMI with TMDS
  encoding in a scanline interrupt using the SIO TMDS encoder.
* Same reasoning applies to USB: prefer the native USB controller (host
  mode) over CPU-hungry PIO-USB for keyboard/mouse.

## Architecture

The Cortex-M33 is ARMv8-M Mainline: Thumb-2 only, no MMU, no banked
processor modes, NVIC instead of a vector-per-mode table.  It therefore
gets its own architecture directory that is searched *before* `arch/arm`,
so that the A-profile assembly (srs/rfe, cps, CP15, banked SPs) can be
replaced file by file while all the portable ARM C code (EABI calling
convention, 32-bit int, ELF loader, ...) is shared:

    ARCH = armv8m arm      (vpath: machine/rp2350, arch/armv8m, arch/arm, generic)

* `ARCH_ARM` stays set (C-level ARM/EABI assumptions still hold).
* New `ARCH_ARMV8M` selects `arch/armv8m`.
* New `MACHINE_RP2350` selects `machine/rp2350`.

### Privilege model

The m68k user/supervisor split maps directly onto the M-profile Thread
mode controls:

| TOS state                  | Cortex-M33                                    |
|----------------------------|-----------------------------------------------|
| user mode, USP             | Thread, CONTROL.nPRIV=1, SPSEL=1 (PSP)        |
| supervisor, own SSP        | Thread, CONTROL.nPRIV=0, SPSEL=0 (MSP)        |
| supervisor on user stack (`Super(0)`) | Thread, nPRIV=0, SPSEL=1 (PSP)     |
| interrupt / exception      | Handler mode (always MSP)                     |

### Traps

`svc #n` keeps its pTOS meaning (trap #n, vector at 0x80 + 4n of the
emulated 68k vector table).  On Cortex-M the SVC exception runs in Handler
mode, where a BIOS call that waits for an interrupt (`bconin()` -> `wfi`)
would deadlock.  The SVC handler therefore only *redirects*: it builds a
fresh exception frame on MSP whose PC is the TOS trap vector and whose LR
is a small return trampoline, and exception-returns into privileged Thread
mode.  The trap handler then runs as ordinary preemptible code.  The
trampoline ends with a reserved `svc #255`, which copies r0 into the
original caller's frame, restores the caller's CONTROL (privilege and
stack selection) and returns to it.

### Memory map

| Region        | Address      | Use                                               |
|---------------|--------------|---------------------------------------------------|
| Flash (XIP)   | 0x10000000   | Cortex-M vector table, IMAGE_DEF block, OS header, .text/.rodata/.data (read-only, as on every other target) |
| SRAM          | 0x20000000   | "low memory": emulated 68k vector table and sysvars (first 2 KB), .low_stram, .bss, stack, then TPA |
| PSRAM (later) | 0x11000000   | 16 MB TPA (IS66WVS16M8FBLL)                        |

`.data` already lives in ROM on every pTOS target, so nothing needs to be
copied to RAM at startup; only .bss is cleared.

### Image format

The bootrom needs an IMAGE_DEF block in the first 4 KB of flash.  The
linked ELF is converted to UF2 (family RP2350-ARM-S) by a small host tool,
so the image can be copied to the BOOTSEL mass-storage drive.

### Console

UART0 is a PL011, the same as on QEMU virt-arm.  The board has no
USB-serial bridge, so a USB-CDC console on the native USB port follows
right after the first UART-only boot.

## Status

2026-09-18: phase 1 done.  pTOS boots on the board to the EmuCON2 prompt
over the USB console (COM port, 1209:0001); builtins and GEMDOS console I/O
work.  No drives yet (phase 2).

Bring-up lessons:

* `#include "x.h"` searches the including file's directory first, so a
  same-named header in `arch/armv8m` or `machine/rp2350` does *not*
  override one next to a generic `.c`/`.h` in `bios/`.  Machine
  differences go into `config.h` (`LOWMEM_BASE`) or `#ifdef` branches.
* A fault before `init_exc_vec()` used to lock the core up (null 68k
  vector); `earlyfault.c` now reports it on the console.
* `CONF_WITH_RP2350_MONITOR`: a 10 ms timer interrupt routed to the NMI
  keeps the USB console alive and reports the PC while the system is stuck
  with interrupts masked or inside a fault handler.
* Opening the USB console at 1200 baud reboots into BOOTSEL.

2026-09-18: phase 2 done.  The microSD slot works through the generic
SD/MMC-over-SPI driver (bios/sd.c) with rp2350_spi.c underneath: FAT16
partitions appear as C:, D:, ...; reading, writing, mkdir, copy tested on
a 4 GB SDHC card with two FAT16 partitions.  Along the way:

* ARMv8-M `delay_loop()` is an exact microsecond wait on TIMER0
  (loopcount_1_msec = 1000); the counted loop was never calibrated on ARM.
* The m68k DMA boot of root sectors is compiled for m68k only.
* The console uses ST high (640x400 mono, 80 columns) instead of ST low.
* USB console: BUFF_STATUS bits are only cleared once handled (a race
  killed the bulk endpoints on bursts), and received data is flow
  controlled into the keyboard IOREC instead of overflowing it.
* sd.c: SD_CSD_TIMEOUT 8 -> 256 bytes; this card needs more than the
  specification's 8, and every timeout was taken for a media change.

2026-09-19: GEM runs.  The AES and desktop are enabled; the desktop comes
up on the 320x240 SPI display (checked through a framebuffer dump over the
USB console: a break makes the monitor print it, `tools/fbshot.ps1` in the
GEMbedded repository turns it into a PNG).  About 95 KB of SRAM go to the
OS, ~360 KB remain for programs.

* `aes/arch/armv8m`: context switch with MSP/PSP/CONTROL instead of banked
  stack pointers (CONTROL kept in the spare `u_regs[12]`), trap #2 keeps
  only the caller's resume record, interrupt hooks run on the main stack.
* Planar screen memory holds *native* words, bit 15 leftmost: that is how
  the VDI fills, lines, raster copies and mouse cursor write it.  The byte
  writers (console, byte-aligned text) go through `SCREEN_BYTE()`
  (include/endian.h), unaligned text through `normal_blit_screen()`.  The
  display DMA moves 16-bit words for that reason.

2026-09-19: GEM usable by touch.  The 2.8" display runs at 25 MHz SPI
(about 20 frames/s), touch works as a mouse (tap = click, double tap,
hold = drag), "Touch calibration..." in the desktop's Options menu fits
nine points by least squares (saved to C:\TOUCHCAL.INF), and a finger on
the screen at boot calibrates before the desktop starts.  Programs reach
the touch driver through the _TCH cookie (include/touch.h, MIT).

Bugs found on the way, most of them in the shared ARM code (they affect
every ARM target):

* `int_timerc()` never called `etv_timer`: no VDI/AES timer at all
  (`evnt_timer()` never returned, no AES timer events).
* `timer_c_sieve` was rotated as a signed WORD: once the sign bit was set
  it stayed 0xffff, so VBL, key repeat and the AES tick ran at 200 Hz --
  double clicks had a third of their time.
* ARM `mouse_int()`: `cur_ms_stat |= ~(1<<5)` set the button bits on every
  motion.
* AES: `gl_bpend` was not decremented when a multi-click button wait was
  cancelled by another event; it only grew, delaying every single click.
* `cur_replace()` restored the mouse background with swapped words on
  little-endian machines (debris behind the pointer).
* `Supexec()` does not exist on ARM (returns EINVFN); use `Ssystem()`.
* rp2350: the monitor's NMI overwrote data the SVC redirect and the GEMDOS
  entry wrote below the stack pointer; interrupts now have their own
  stack; AES stacks are 1536 LONGs.

The AES cancels its wait for a second click when the mouse moves more
than 2 pixels (`mchange()`); the touch driver therefore keeps the pointer
still during a tap.

2026-09-19: a drive in the flash, and the real-time core out of it.

* The real-time runtime copies itself into core 1's SRAM at start-up
  (rtcore, GEMbedded repository).  Core 1 no longer reads the flash at all,
  so writing the flash cannot stall it -- and the worst lateness of the
  stepper demonstrator fell from 25 to 8 us, the rest having been cache
  misses in the XIP cache shared with core 0.
* `CONF_WITH_RP2350_FLASHDISK`: 4 MB of the flash as drive F:, FAT16,
  formatted on first use.  Underneath it a translation layer with wear
  levelling (bios/machine/rp2350/rp2350_flashdisk.c): sectors are never
  overwritten in place but written to a free slot and tagged, the old copy
  marked obsolete, blocks reclaimed when free ones run short, new blocks
  taken by lowest erase count, and now and then a cold block moved so that
  unchanging data wears too.  A power failure loses at most the sector
  being written.
* The erase/program routine runs from SRAM (.ramtext, copied by
  startup.S), with interrupts and the monitor's NMI masked: nothing may
  execute from flash meanwhile.  QSPI pads, the CS1 (PSRAM) configuration
  and XIP are restored around it, using the bootrom's own set-up code.

2026-09-19: programs arrive over USB.  `_UCN` (include/usbcon.h, MIT)
hands the USB console to a program byte for byte ("raw mode"), instead of
turning what arrives into keystrokes.  DEPLOY.PRG (GEMbedded repository)
uses it: while it runs, it accepts a transfer, writes it to F: and runs
it; nothing can be sent to a machine that is not running it.  The host
side is tools/ptosdeploy.py (or .ps1).  First successful deploy: 39 KB
over USB onto the flash drive and started, without SD card or reboot.

## Phase 1 steps

1. Kconfig/Makefile: `MACHINE_RP2350`, `ARCH_ARMV8M`, CPU flags, UF2 image
   target, config `rp2350_defconfig` (CLI only, no AES).
2. Linker script: ROM at 0x10000000, stram at 0x20000000.
3. `bios/machine/rp2350/startup.S`: vector table, IMAGE_DEF, OS header,
   reset handler (stack, .bss clear, biosmain).
4. Clocks (XOSC + PLL_SYS), resets, UART0 on GPIO0/1.
5. `arch/armv8m`: SVC redirect, fault handlers -> panic, interrupt masking
   (PRIMASK), SysTick-driven 200 Hz tick into `int_timerc()`.
6. GEMDOS entry (`rwa.S`), `Super()`, process start (`gouser`) for the new
   privilege model; `setjmp`, `trap1`, `cmdasm.S`.
7. UF2 conversion tool.
8. USB-CDC console.

Later phases: microSD (SPI1), PSRAM as TPA, video (HSTX), USB HID, core 1
for applications.
